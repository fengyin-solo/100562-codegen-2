# 城市集中供热管网与换热站运行管理平台

面向一次二次管网台账、换热站运行、水力平衡调节、热计量抄表、抢修处置、停暖通知与热费结算的一体化城市集中供热运行管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 用热稽查与违规处理台账

侧边栏「用热稽查与违规处理」（路由 `/heatviolation`）把偷热、私接、改表等违规用热案件
收拢成一册，一张案件单从立案一路流转到处理决定。规则集中在
`frontend/src/api/violation-service.ts`，页面不做业务判断；专用数据（卷宗、勘察记录、热费待办）
存在 localStorage 的 `district-heating:violation` 键下，与通用台账分开。

- **单行道流转**：立案 → 取证 → 告知 → 决定，只能提交当前这一步，缺一步不许跳级；
  已作出决定的卷宗封卷，不许倒回立案或改任何材料。
- **现场取证两人签字**：取证材料必须两名稽查人员共同签字，缺一或同一人签两次都不能提交。
- **追补附计量记录**：处理决定涉及追补热费时，必须附计量单号与表码前、后读数。
- **断点续录**：任何一步材料不齐或提交中断（可勾选「模拟下一次提交失败」演示），已填内容
  暂存在该步骤，之后从失败那一步接着录，不回退。
- **案由统一口径**：案件卷宗与勘察记录两处共用 `CASE_REASONS` 同一套案由；不符合口径
  （含缺失）的先挂起，按口径核定后在原步骤继续。
- **去重**：同一用户、同一用热地址且仍在办的立案材料重复提交只落一条；已办结的可另立新案。
- **办结落待办**：作出决定后自动生成热费待办，受理后写入「热费结算」清单的「追补待核算」单，
  该页顶部也有「用热稽查追补待算」面板。
- 重置：页面「重置示例数据」，或清掉 `district-heating:violation` 键。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `district-heating:entries` 这一项，或调用 `resetModule(模块)`。
